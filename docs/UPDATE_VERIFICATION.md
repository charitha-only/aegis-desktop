# Offline signed update verification preview

```text
node aegis-cli/bin/aegis.js verify-update <artifact> <envelope.json> <trusted-public-key.pem> <trusted-policy.json>
```

This developer command only verifies existing local files. It neither downloads nor stages, installs or executes an update, and it never writes the trusted policy. The runtime updater IPC stays disabled. Success authenticates bytes relative to the supplied Ed25519 public key; it is not an OS code-signing certificate or independent publisher identity check.

Provision the public key (SPKI PEM, PUBLIC KEY header) and policy independently of the downloaded artifact/envelope. Never trust a key or policy supplied by the update being checked. Keep the publisher private key outside application code, source control, logs and distributed artifacts. No production key is bundled or generated by this tool.

Trusted policy has exactly these fields:

```json
{"appId":"org.example.app","platform":"windows","architecture":"x64","currentVersion":"1.0.0","maxSeenSequence":7}
```

Use the real application's installed version and trusted sequence floor. Platforms: windows/linux/macos; architectures: x64/arm64. Versions have exactly three numeric components, no leading zeroes or prerelease/build suffixes; each component fits u32. The release version and sequence must both advance. Policy/clock inputs are trusted: this verifier does not protect them from same-account edits, system-clock rollback or disk snapshots.

The envelope has exactly `schemaVersion: 1`, `payload` and `signature`. Both byte values use canonical padded base64. Decode payload as UTF-8 JSON with exactly:

```json
{"schemaVersion":1,"appId":"org.example.app","platform":"windows","architecture":"x64","version":"2.0.0","sequence":8,"expiresAt":1893456000000,"artifact":{"size":3,"sha256":"ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"}}
```

This illustrative artifact is the three bytes `abc`, not a deployable update. `expiresAt` is Unix milliseconds and must be after the verification clock. Sequence is a positive safe integer. Payload bytes must equal UTF-8 `JSON.stringify(JSON.parse(payload))`: no whitespace, BOM, duplicate fields or alternative numeric/string encodings. Property order is retained, not sorted; this is a project-specific wire form, not RFC 8785 canonical JSON.

Sign the byte concatenation `UTF8("AEGIS_UPDATE_V1") || 0x00 || payload` with Ed25519. The signature is 64 bytes. Node's signing/verifying algorithm argument is null for Ed25519. The verifier rejects unknown fields/schema versions and checks the signature before interpreting signed metadata. It never follows metadata-provided paths or URLs. The artifact is a separate explicit local path.

Input files must be ordinary files. Caps: envelope 128 KiB, decoded payload 64 KiB, public key/policy 8 KiB each, artifact 1 GiB. Artifact reads stream with the signed size enforced and SHA-256 checked. File/clock changes after verification are not covered: a future installer must consume the exact verified bytes through a controlled transaction and recheck before application.

Success returns target/version, digest/size, expiry and `nextSequence`, with `publisherAuthenticated: true` and `autoApply: false`. It does not persist rollback state. The application must define durable sequence/current-version handling and safe retry/recovery semantics; verification alone cannot make a failed install recoverable. Reusing a sequence at or below the supplied floor is rejected. Do not treat this stateless check as a complete automatic updater.

Public API/CLI tests cover valid signatures, wrong publishers, changed metadata/artifacts, target mismatch, expiry, old/equal versions/sequences, malformed schema/encoding, private-key input, oversized metadata and policy preservation. The native fixture signs a copied actual core binary using an ephemeral in-memory test key, verifies via CLI, then alters a byte and expects rejection. It installs nothing. These test keys do not establish a production publisher.

Remaining gates: securely provisioned/rotated owner keys, threshold/revocation policy, persisted rollback/retry state, transactional install/recovery, installer/code signing, physical interruption tests and independent review. This preview is not TUF compliance. Design references: [Node crypto API](https://nodejs.org/api/crypto.html) and [TUF's security design](https://theupdateframework.io/docs/security/).
